### Security blokkers vóór klant-launch — 3 fixes ✅ (18:35)

Korte audit vond 3 kritieke issues. Allemaal gefixt + bewezen:

| # | Issue | Fix | Bewijs |
|---|---|---|---|
| 1 | JWT_SECRET hardcoded in `lib/auth.js:3` | `setSecret()` valideert nu (>=32 chars), `getSecret()` throwt bij missing — geen hardcoded fallback meer | grep findt 'm niet meer |
| 2 | `req.userId = ... \|\| 0` fallback in authMiddleware | Throw 401 als token geen geldige `userId>=1` heeft — voorkomt user_id=0 data-pollution | code-check |
| 3 | Geen rate-limit op `/api/login` (brute-force mogelijk) | In-memory Map per IP, 5 fails/15min → 429 + `Retry-After`, success = reset. `setInterval` cleanup elke 5 min. | curl-test: 5×401 → 6e=429 |
| 4 | Bonus: wrong creds gaf HTTP 200 met `{ok:false}` | 401 ipv 200 voor onjuiste login | bevestigd |

**Crucial config**: `app.set("trust proxy", "loopback")` zodat cloudflared via 127.0.0.1 proxy-IPs correct doorgeeft. Anders zou 1 brute-forcer iedereen locken (zelfde 127.0.0.1 voor allen).

**SSH-disconnect-fix (parallel)**: `/tmp/fix-ssh-keepalive.sh` aangemaakt — voegt `ClientAliveInterval 30` toe aan sshd_config. User runt via `! sudo bash`. `~/.bashrc` tmux-autoattach toegevoegd: volgende `ssh t4c` landt in tmux-sessie "main", drop = `ssh t4c` opnieuw = direct terug.
