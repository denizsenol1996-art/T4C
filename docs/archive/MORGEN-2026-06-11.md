# Morgen-checklist — 2026-06-11

> Gemaakt 2026-06-10 's avonds nadat Jurgen tegen "Deze app is geblokkeerd"-melding aanliep bij Google.

## TOP-1 — Google-login situatie uitzoeken

### Stap 0 — eerst wéten waar de blokkade vandaan kwam
Vraag Jurgen 's ochtends:
- **Wáár** kreeg hij gisteren de "Deze app is geblokkeerd"-melding? (Tailscale? MCP? Search Console? Iets anders?)
- Welk Google-account probeerde hij in te loggen?

→ Zonder dit weten we niet of T4C-bouwwerk het probleem oplost of niet.

### Stap 1 — beslis WAT we bouwen in T4C
Twee heel verschillende klussen, gisteren niet beslist:

**Optie A — "Login met Google" knop op T4C (alleen identiteit)**
- Doel: dealers + Jurgen kunnen inloggen op T4C met hun Google-account, geen wachtwoord meer nodig.
- Scopes: alleen `openid email profile` → **GEEN verificatie-blokkade van Google**.
- Werk: ~2-3u
  1. OAuth-client aanmaken in Google Cloud Console (Jurgen's eigen project, redirect URI = `https://t4c.../auth/google/callback`).
  2. `client_id` + `secret` in T4C `.env`.
  3. Route `/auth/google` + `/auth/google/callback` in `t4c-server` (passport-google-oauth20 of handmatig).
  4. Callback: match user op `email` in `users`-tabel, anders nieuwe user aanmaken met flag `auth_provider='google'`.
  5. Knop op `/login` naast bestaande wachtwoord-form.
  6. Test met Jurgen's eigen Google-account.

**Optie B — Google-data lezen vanuit T4C (Gmail/Drive/Agenda)**
- Doel: bijv. taxatie-mails uit Gmail tonen in T4C, of foto's uit Drive trekken.
- Scopes: sensitive (gmail.readonly / drive.readonly).
- **Loopt tegen dezelfde "Deze app is geblokkeerd" aan** tenzij we Google-verificatie doorlopen (privacy-policy publiceren, security-review, kost weken).
- Workaround voor 1-user: Jurgen kan zichzelf als "test-user" toevoegen in Google Cloud Console → app blijft unverified maar werkt voor zijn eigen account. Niet schaalbaar naar dealers.

### Stap 2 — uitvoeren
Pas keuze A of B (of beide) bouwen NA expliciete go van Jurgen 's ochtends. Niet impulsief beginnen.
